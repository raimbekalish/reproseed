# ReproSeed 0.1.0 release notes

Draft for the first publication. These notes are not a release. Version `0.1.0` is unpublished. The manifest does not set `private`, and this file has no release date. The changelog heading stays `Unreleased` until the owner publishes. On that day, move the changelog section to `0.1.0`, date it, and require a fresh green CI run on that exact commit before a tag or publish.

## What 0.1.0 does

`reproseed minimize` replays a failing scenario in Chromium, removes steps that are not required for the same failure, and writes a Playwright regression test.

Step minimization drops one step at a time and keeps a step when dropping it stops that failure from coming back. The verified result is `verified-one-minimal`: 1-minimal under single deletion of that ordered scenario. It is not a proof of the globally shortest reproduction. Five fresh verification replays must reproduce the original failure signature. Those five replays do not use the candidate cache. A regression spec is written only after that verification.

Two oracles are included:

- Record count, used by the duplicate-submit example. The failure codes are `DUPLICATE` and `COUNT_MISMATCH`.
- DOM text, used by the stale-search example. The failure code is `DOM_MISMATCH`.

`--tune-delays` is off unless the command includes it. After a verified step minimization, it may try shorter network delays for one kept delay step. Several kept delay steps are skipped. A shorter delay is exported only when a new minimization and five fresh replays still reproduce the original failure. Otherwise the original verified scenario is exported unchanged. The race is not treated as monotonic. The default grid is 250ms, with at most 36 timing replays, 180000ms of timing-stage wall clock, and at most 4 coarse and 4 fine durations.

## Examples

Both examples are authorized loopback applications. Reset stays disabled until `REPROSEED_APP_ID` and `REPROSEED_RESET_AUTHORIZATION` are set. The demo commands serve the buggy page. Fixed pages exist only for the repository's RED/GREEN tests.

- Duplicate submit listens on `http://127.0.0.1:4010`. A second submit during a delayed POST creates a second record. The oracle expects one record.
- Stale search listens on `http://127.0.0.1:4020`. A delayed response for an older query can overwrite the current result. The oracle expects `Results for beta`.

## Safety boundary

Reset is allowed only for `http` on `127.0.0.1`, `localhost`, or `::1`, with no userinfo, path, query, or fragment, when `REPROSEED_APP_ID` matches `GET /__reproseed/identity` and `REPROSEED_RESET_AUTHORIZATION` is accepted by `POST /__reproseed/reset`. The credential is an environment variable. It is not a flag, and scenario JSON does not expand `${...}` or `$(...)`. Redirects are refused. Reports omit the credential.

Production websites, signed-in applications, and hosts outside loopback are unsupported.

## Tested environments

- GitHub-hosted Ubuntu with Node.js 22. CI installs Playwright 1.64.1 and launches its downloaded Chromium with `channel: "chromium"`, not system Chrome and not `chrome-headless-shell`.
- macOS for development. A read-only dry run on 25 October 2026 used Node.js 24.11.0, packed the then-current tree, installed that tarball outside the checkout, and ran both examples through `verified-one-minimal`, RED on the buggy pages, and GREEN on the test-only fixed pages.

`package.json` allows Node.js 22 or newer. Windows has not been tested. Do not describe any other operating system or Node version as supported from these runs.

## Known limitations

- `verified-one-minimal` is 1-minimal under single deletion. It does not try new step orders, and it is not a global shortest-path proof.
- A shorter network delay that fails does not prove that every longer delay would succeed.
- Only one kept delay step is tuned. Several kept delay steps are left unchanged.
- The npm package contains the CLI, `LICENSE`, `README.md`, the two example scenario files, and compiled `dist/`. It does not contain the demo servers or this notes file. A generated spec imports `@playwright/test`, which is a development dependency and is not installed with the package. The person running that spec installs `@playwright/test` and Chromium at this Playwright version.
- There is no AI integration, hosted service, dashboard, or database.
- The manifest is publishable, and no version is on the npm registry. [publish-runbook.md](publish-runbook.md) is the remaining publication procedure. This draft does not perform it.
