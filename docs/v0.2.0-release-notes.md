# ReproSeed 0.2.0 release notes

Pending publication. This file describes the candidate in this repository. It is not a GitHub Release, and `0.2.0` is not on npm. The published release remains `0.1.0` (October 25, 2026) until the owner publishes this version. The changelog heading is [0.2.0] in [CHANGELOG.md](../CHANGELOG.md), marked pending publication, with no date. The date is added later, in a release-finalization commit, and that commit is the one CI verifies before publication. The order is [v0.2.0-release-checklist.md](v0.2.0-release-checklist.md). Do not treat these notes as the historical [0.1.0 notes](v0.1.0-release-notes.md).

`npm install reproseed` and `npm install reproseed@0.1.0` install published `0.1.0`. That package can `minimize`. It does not include `init`, `doctor`, `--trace`, or the guides named below. A checkout of this candidate, and a tarball packed from it, print `0.2.0` from `--version`. That printout is the candidate version. It is not evidence that the registry serves `0.2.0`.

## What 0.2.0 adds

`reproseed init` writes a starter scenario for the record-count or DOM-text oracle. It does not contact a server, and it does not put a reset credential or a production URL in the file.

`reproseed doctor` checks a scenario, the loopback target, Chromium, and the clean-state GET. It sends GET requests only. It does not send `POST /__reproseed/reset`, and it does not launch a browser. `reset-accepted` and `clean-state-after-reset` stay `not-verified`. For a record-count scenario, `oracle.request.path` has to return records with string `id`, `email`, and `note`, and numeric `createdAt`. `reset.verify.path` only has to return a JSON array. The paths may differ.

`reproseed minimize --trace <file>.zip` records one Playwright trace after `verified-one-minimal`. The evidence replay is separate from the five verification replays and is omitted from replay counts. Tracing stays off when the flag is omitted. A zip is verified evidence only when that replay reproduces the verified failure. A failed capture does not replace an existing zip and says that file may be stale. A trace failure does not change the minimization exit code.

The npm tarball includes [integrate-your-app.md](integrate-your-app.md) and [trace-evidence.md](trace-evidence.md). Published `0.1.0` does not include those files. The example servers, including `examples/opt-in-ticket`, stay in the git repository and are not in the package.

A fresh install of the packed candidate, outside this repository, was used to check the public path: `--version` prints `0.2.0`, the CLI starts without the source checkout, `init` writes a scenario, `doctor` does not reset the target, `minimize` reaches `verified-one-minimal` with five fresh verification replays, the generated spec asserts the intended oracle, `--trace` produces a zip, that spec fails on the buggy opt-in page and passes on the test-only fixed page, and Trace Viewer opens the zip. Running the exported spec needs a separate `@playwright/test@1.64.1` install. The candidate does not install that package.

## Browser test-harness process safety

This is a test-harness change, not a new CLI command. Browser tests stop a child the test spawned by calling that `ChildProcess` handle's `kill`, so a reused numeric PID is not signalled. A Chromium descendant is signalled only after a fresh parent-chain and browser-command check. A process whose ownership cannot be proven, including one reparented to init, is reported and left running. PID 0, PID 1, a process group, and the test runner are not signalled.

## Backward compatibility

`reproseed minimize scenario.json` still writes a report and, after `verified-one-minimal`, a Playwright spec. Exit `0` is still `verified-one-minimal`. Exit `1` is still usage. Exit `2` is still an unstable or unreproduced result. Exit `3` is still a budget stop. Exit `4` is still an internal failure. A trace request does not change those codes.

Five fresh verification replays are still required. They do not use the candidate cache. `verified-one-minimal` still means 1-minimal under single deletion, not a proof of the globally shortest scenario. Optional `--tune-delays` still exports a shorter delay only when a new minimization and five fresh replays reproduce the original failure.

Reset still requires `REPROSEED_RESET_AUTHORIZATION` from the environment. Scenario JSON still does not carry the credential. Loopback rules are unchanged: `http` only, hosts `localhost`, `127.0.0.1`, and `::1`. Output files still stay inside the current directory. Replacing an existing report, spec, scenario, or trace still requires `--force`.

## Installation requirements

Node.js 22 or newer. Tested on macOS for development and on GitHub-hosted Ubuntu 24.04 with Node.js 22. Windows is not tested.

Chromium is separate. It is Playwright `1.64.1`'s downloaded Chromium, `channel: "chromium"`, not system Chrome and not `chrome-headless-shell`:

```bash
npx playwright install --with-deps --no-shell chromium
```

A generated spec imports `@playwright/test`. Installing `reproseed` does not install it:

```bash
npm install --save-dev @playwright/test@1.64.1
```

Three installs, and they are not the same package:

1. Published npm `0.1.0`: `npm install reproseed@0.1.0`. `--version` prints `0.1.0`. `minimize` is present. `init`, `doctor`, `--trace`, and the two guides are absent. `npm install reproseed` with no version stays on `0.1.0` until `0.2.0` is published.
2. Unpublished source or tarball candidate `0.2.0`: `npm pack` from this repository writes `reproseed-0.2.0.tgz` because `package.json` is `0.2.0`. Install that file in another directory. `--version` prints `0.2.0`. `init`, `doctor`, `--trace`, and the two guides are present. This is not what the registry serves.
3. Future published npm `0.2.0`: `npm install reproseed@0.2.0`, after the owner publishes. `--version` prints `0.2.0`. The commands and guides match the candidate. That version is not on npm yet. After publication, `npm install reproseed` with no version installs `0.2.0`.

Installed packages use `npx reproseed`. `node dist/cli.js` is for a source checkout. Example servers are not in any npm install.

## Known limitations

- `verified-one-minimal` is 1-minimal under single deletion. It is not a global shortest-reproduction proof.
- Doctor does not send reset. `reset-accepted` and `clean-state-after-reset` stay `not-verified`.
- While the application is still buggy, the generated spec fails. That is RED. The same spec passes after the application is fixed. That is GREEN. The spec asserts the intended oracle, not the observed failure.
- Trace status `verified` means the evidence replay failed with the same target signature and the zip was saved. `not-reproduced` saves a zip that is not verified evidence. `failed` does not save a new zip. An existing zip may be stale.
- Playwright's trace save cannot be cancelled. A late save is still waited on, and the temporary zip is deleted after that call settles. Killing the process can leave Playwright's temporary files outside `artifacts/`.
- Library traces do not record `@playwright/test` `expect` assertions. The zip can contain page text, input, screenshots, and network bodies. ReproSeed does not redact them.
- A Chromium descendant that is not the direct child can still be signalled by numeric PID after the ownership check. A browser reparented to init is reported and not killed.
- The example servers and these release notes are not in the npm package.
- Production sites, HTTPS origins, and non-loopback hosts are unsupported.
- Windows is not a tested operating system.
