# v0.2.0 release-candidate checklist

This file prepares `0.2.0`. It is not a release, a tag, or permission to publish. `package.json` stays at `0.1.0` until the owner publishes. Tag `v0.1.0` stays on the `0.1.0` commit. Do not create tag `v0.2.0` or a GitHub Release from this checklist.

Publication mechanics, when the owner later approves them, still follow [publish-runbook.md](publish-runbook.md). Recheck the facts in that runbook on publication day. They were recorded for `0.1.0`. The [0.1.0 checklist](release-checklist.md) is the record of that release. Do not rewrite it.

## Since 0.1.0

These commands are in this repository and are absent from published `0.1.0`:

- `reproseed init` writes a starter scenario. It does not contact a server.
- `reproseed doctor` checks a scenario with GET requests only. It does not send reset, and it does not launch a browser.
- `reproseed minimize --trace <file>.zip` writes one Playwright trace after `verified-one-minimal`. Tracing stays off when the flag is omitted.
- The npm package includes `docs/integrate-your-app.md` and `docs/trace-evidence.md`.

The dependency `playwright` is pinned to `1.64.1`. `@playwright/test` stays a dev dependency at the same version. A generated spec imports `@playwright/test`. Installing `reproseed` does not install it.

## Backward compatibility

- `reproseed minimize scenario.json` still writes a report and, after `verified-one-minimal`, a Playwright spec.
- Exit `0` is still `verified-one-minimal`. Exit `2` is still an unstable or unreproduced result. Exit `3` is still a budget stop. A trace request does not change those codes.
- Five fresh verification replays are still required. They do not use the candidate cache. `verified-one-minimal` still means 1-minimal under single deletion, not a proof of the globally shortest scenario.
- Reset still requires `REPROSEED_RESET_AUTHORIZATION`. The value is still read from the environment, not from scenario JSON, and it is still omitted from reports and specs.
- Loopback rules are unchanged: `http` only, hosts `localhost`, `127.0.0.1`, and `::1`, no userinfo, path, query, or hash, and redirects are refused.
- Output files still stay inside the current directory. Replacing an existing report, spec, scenario, or trace still requires `--force`. A trace path still has to end in `.zip` and still cannot replace the scenario, report, or spec path.

## Known limitations

- `verified-one-minimal` is not a global shortest-reproduction proof.
- Doctor's `reset-accepted` and `clean-state-after-reset` stay `not-verified`. Doctor does not send reset.
- `reset.verify.path` is a JSON array that is empty after an authorized reset. Items do not have to be records. `oracle.request.path` for `record-count` has to return records with string `id`, `email`, and `note`, and numeric `createdAt`. The paths may differ. A `dom-text` oracle does not use that record list.
- While the application is still buggy, the generated spec fails. That is RED. The same spec passes after the application is fixed. That is GREEN. The spec asserts the intended oracle, not the observed failure.
- Trace status `verified` means the evidence replay failed with the same target signature and the zip was saved. `not-reproduced` publishes a zip that is not verified evidence. `failed` does not publish a new zip. An existing zip at that path is left unchanged and may be stale.
- Playwright's trace save cannot be cancelled. A save that misses the 5 second budget is still waited on, and the temporary zip is deleted after that call settles. Killing the process can leave Playwright's own temporary files outside `artifacts/`. Those files are not the `--trace` path.
- Library traces do not record `@playwright/test` `expect` assertions. `npx playwright show-trace <file>.zip` opens the zip. The trace can contain page text, input, screenshots, and network bodies. ReproSeed does not redact them.
- The example servers and `examples/opt-in-ticket` are not in the npm package.
- Production sites, HTTPS origins, and non-loopback hosts are unsupported.
- Windows is not a tested operating system.

## Installation

Three installs. They do not offer the same commands. Example servers are not in any of them. Chromium and `@playwright/test` are separate in every case:

```bash
npx playwright install --with-deps --no-shell chromium
npm install --save-dev @playwright/test@1.64.1
```

Published `0.1.0` (`npm install reproseed@0.1.0`) provides `minimize`. It does not provide `doctor`, `init`, or `--trace`, and it does not include the guides. `npm install reproseed` with no version stays on `0.1.0` until `0.2.0` is published.

The unreleased candidate is a tarball from this repository, installed in another directory with `npm install /absolute/path/reproseed-0.1.0.tgz`. `--version` prints `0.1.0`. `npx reproseed doctor --help`, `npx reproseed init --help`, and `npx reproseed minimize --help` show `doctor`, `init`, and `--trace`. The guides are `node_modules/reproseed/docs/integrate-your-app.md` and `node_modules/reproseed/docs/trace-evidence.md`.

After publication, `npm install reproseed@0.2.0` provides those same commands and guides, and `--version` prints `0.2.0`. That version is not on npm yet.

## Test environments

- Development: macOS, Node.js 22.
- CI: GitHub-hosted `ubuntu-24.04`, Node.js 22. The three jobs are Quality and build, Chromium integration, and Package smoke verification.
- Chromium is Playwright `1.64.1`, installed with `npx playwright install --with-deps --no-shell chromium`.
- Do not list Windows, system Chrome, or a production site as supported.

## Security and privacy

- Reset authorization comes only from `REPROSEED_RESET_AUTHORIZATION`.
- Do not commit `.env`, reports, generated specs, or `*.zip` traces.
- Do not upload traces to GitHub Actions artifacts or send them outside the machine.
- Report a vulnerability through the private advisory form in [SECURITY.md](../SECURITY.md). A public issue is only for a defect that is safe to describe, with credentials removed.

## Publication checks

Run these only after the owner approves a version bump in a later change. This checklist does not perform them.

- [ ] `package.json` version is `0.2.0`, and the changelog moves `Unreleased` to `0.2.0` with a date.
- [ ] `main` and `origin/main` match the commit that will be tagged.
- [ ] All three CI jobs passed on that commit.
- [ ] `npm pack --dry-run --json` lists `package.json`, `LICENSE`, `README.md`, `dist/`, the two example scenario files, `docs/integrate-your-app.md`, and `docs/trace-evidence.md`.
- [ ] The tarball has no `src/`, `node_modules/`, `.env`, `artifacts/`, reports, traces, demo servers, or the opt-in example.
- [ ] A fresh install of that tarball runs `--version`, `--help`, `init`, `doctor`, and `minimize` without the source checkout.
- [ ] `npm view reproseed version` and the npm account's 2FA state are rechecked that day.
- [ ] `npm publish` is run by the owner from a trusted machine, not from CI.
- [ ] Tag `v0.2.0` is created on the published commit after the registry accepts the version. Do not move `v0.1.0`.
- [ ] The GitHub Release notes match the changelog and do not include credentials or traces.

## Rollback and incident response

- npm versions are immutable. Do not republish `0.2.0` onto a different tarball.
- Do not move tag `v0.1.0` or tag `v0.2.0`.
- If the published tarball is wrong, publish `0.2.1` with the correction, or deprecate `0.2.0` with `npm deprecate` and tell users to install `0.1.0` or `0.2.1`. `npm unpublish` is not the plan.
- `0.1.0` remains the last published release until `0.2.0` is actually on the registry.
- A vulnerability uses the private advisory process in [SECURITY.md](../SECURITY.md).
- A non-exploitable defect uses a public issue with credentials and traces removed.
